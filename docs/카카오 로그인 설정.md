# 카카오 로그인 설정

카카오 개발자 콘솔에서 해야 할 일과, 그 값을 어디에 넣는지 정리합니다.

> **앱 키 발급은 6단계 중 1단계입니다.** 나머지를 빠뜨리면 로그인이 `KOE004`·`KOE006`으로 막힙니다.

## 콘솔 체크리스트

| # | 단계 | 위치 | 빠뜨리면 |
|---|---|---|---|
| 1 | 앱 생성 → **REST API 키** 복사 | [내 애플리케이션] | — |
| 2 | 플랫폼 등록 (Web 사이트 도메인) | [앱 설정] > [플랫폼] | 로그인 진입 불가 |
| 3 | **카카오 로그인 활성화 ON** | [카카오 로그인] > [활성화 설정] | `KOE004` |
| 4 | **Redirect URI 등록** | [앱] > [플랫폼 키] > [REST API 키] | `KOE006` |
| 5 | 동의항목에서 **닉네임을 필수 동의**로 | [카카오 로그인] > [동의항목] | 닉네임이 빈 문자열로 가입 |
| 6 | **Client Secret "사용함"** + 코드 복사 | [앱 설정] > [보안] | 부팅 실패 (아래 참고) |

### Redirect URI

`main.ts`의 `setGlobalPrefix('api/v1')` 때문에 경로에 `/api/v1`이 포함됩니다.

```
로컬  http://localhost:4000/api/v1/auth/kakao/callback
운영  https://<api 도메인>/api/v1/auth/kakao/callback
```

**프로토콜·도메인·포트·경로·마지막 슬래시까지 문자 단위로 같아야** 합니다. 한 앱에 여러 개 등록할 수 있으므로 로컬과 운영을 같은 앱에서 병행해도 됩니다.

## `.env` 반영

```dotenv
KAKAO_CLIENT_ID=<REST API 키>
KAKAO_CLIENT_SECRET=<[보안] 탭의 Client Secret 코드>
KAKAO_CALLBACK_URL=<위 Redirect URI 와 문자열까지 동일>
KAKAO_SCOPE=
FRONT_ORIGIN=http://localhost:3000
```

### `KAKAO_CLIENT_SECRET`을 비울 수 없는 이유

`passport-kakao`는 값이 비면 **`'kakao'`라는 리터럴 더미로 바꿔 넣고**, 그 아래 oauth 라이브러리는 토큰 요청에 `client_secret`을 **항상** 싣습니다. 즉 "안 보내기"가 구조적으로 불가능합니다.

콘솔에서 Client Secret이 꺼져 있으면 카카오가 그 더미를 무시해 동작하지만, 켜져 있으면 토큰 교환이 실패합니다. **실패는 사용자가 동의를 마친 뒤에야** 드러나고 원인은 카카오 응답 본문에만 남습니다.

그래서 이 저장소는 **빈 값이면 부팅을 실패시킵니다.** 애매한 상태로 뜨는 것보다 낫습니다.

### `KAKAO_SCOPE`

비우면 `profile_nickname`만 요청합니다. 생략해도 콘솔 설정대로 동의 화면이 뜨지만, **이미 가입한 사용자에게 추가 동의를 다시 물으려면 scope를 실어 보내야** 합니다.

**콘솔에 켜지지 않은 항목을 보내면 인가 요청 자체가 거부됩니다.** 콘솔 설정과 반드시 일치시키세요.

## ⚠️ 전화번호는 당장 받을 수 없습니다

`phone_number` 동의항목은 **비즈 앱 전환 → 비즈니스 인증(사업자등록번호) → [추가 기능 신청] > [개인정보 동의항목] 심사**를 통과해야 합니다. 기본 제공 항목은 닉네임·프로필 사진·썸네일뿐입니다.

그래서 **온보딩에서 직접 입력받습니다** — `PATCH /users/me`의 `phone` 필드. `010-1234-5678`·`+82 10-1234-5678` 어느 쪽으로 넣어도 E.164로 저장됩니다.

심사가 통과되면 `.env`의 `KAKAO_SCOPE=profile_nickname,phone_number` 한 줄만 바꾸면 됩니다. 재배포는 필요 없고 컨테이너 재생성으로 충분합니다. 사용자가 온보딩에서 넣은 번호는 카카오 값이 덮지 않습니다(`AuthService.kakaoLogin`이 비어 있을 때만 채웁니다).

## ⚠️ 운영 서버에는 아직 붙일 수 없습니다

두 가지가 각각 막고 있습니다.

1. **카카오 플랫폼 도메인은 IP를 받지 않습니다.** 현재 운영은 IP 접속이라 등록이 안 됩니다.
2. **설령 등록해도 로그인이 완성되지 않습니다.** 세션 쿠키가 운영 환경에서 `Secure`로 발급되는데(`cookie.constant.ts`), **HTTP 응답의 `Secure` 쿠키는 브라우저가 저장하지 않습니다.** 카카오 인증이 성공하고 리다이렉트까지 와도 로그인이 안 된 것처럼 보입니다.

→ **도메인 확보 + HTTPS 전환이 선행 조건**입니다. [배포 가이드](배포%20가이드.md)의 "HTTPS로 전환하기"와 같은 조건입니다.

> 도메인 구매 전에 시험해 보려면 `nip.io`·`sslip.io`(예: `http://3-35-1-2.nip.io`)를 쓸 수 있습니다. 실제 도메인 형식이라 카카오 등록도 되고 Let's Encrypt HTTP-01 챌린지도 통과하므로, 그대로 `DOMAIN`에 넣어 기존 certbot 절차를 태우면 HTTPS까지 함께 풀립니다.

## 로컬 검증

```bash
pnpm start:dev

# 1. 우리가 만드는 인가 URL부터 (카카오 통신 없음)
curl -sD- -o /dev/null http://localhost:4000/api/v1/auth/kakao | grep -i ^location
```
`redirect_uri`를 URL 디코드해 콘솔 등록값과 문자 단위로 비교하고, `client_id`와 `scope`를 확인합니다.

```
# 2. 브라우저로 http://localhost:4000/api/v1/auth/kakao 접속
#    동의 → http://localhost:3000/onboarding 으로 이동
#    개발자도구 > Application > Cookies 에 player_session · player_refresh 확인
```

```bash
# 3. 발급된 쿠키로 프로필 조회 (신규 유저는 phone: null)
curl -b "player_session=<쿠키값>" http://localhost:4000/api/v1/users/me

# 4. 온보딩 입력
curl -X PATCH http://localhost:4000/api/v1/users/me \
  -b "player_session=<쿠키값>" -H 'Content-Type: application/json' \
  -d '{"region":"서울","selfLevel":"L2","phone":"010-1234-5678"}'
```

실패하면 서버 로그의 `[KakaoRedirectFilter]` 줄에서 카카오가 준 원인(`KOE####`)을 읽습니다.

## 자주 막히는 지점

| 증상 | 원인 |
|---|---|
| 부팅 시 `KAKAO_...가 비어 있습니다` | `.env` 값 누락. 이 문서의 `.env` 절 참고 |
| `KOE004` | 3단계 (카카오 로그인 활성화) |
| `KOE006` | 4단계. `/api/v1` 누락이 가장 흔함 |
| 동의 후 `/login?error=INTERNAL_ERROR` | 토큰 교환 실패. 서버 로그에서 실제 원인 확인 |
| 로그인은 됐는데 세션이 안 붙음 | HTTP 운영 환경의 `Secure` 쿠키 문제 (위 참고) |
